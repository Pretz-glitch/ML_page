## Definition of done

A public repository that contains:

- [ ] A reproducible station-day table (26,085 rows) built from the raw UCI archive.
- [ ] A train-only preprocessing pipeline with a documented temporal split.
- [ ] A fault injector covering spike, drift, and correlation-break faults, with unit tests.
- [ ] Detection results for MAD, Isolation Forest, and Mahalanobis across three fault types and five seeds.
- [ ] Attribution-faithfulness results for at least two local explanation methods.
- [ ] A descriptive analysis of flags in the unlabelled real record, including three case studies.
- [ ] All result tables and figures generated by scripts, not by hand.
- [ ] An 8–10 page report and a slide deck.
- [ ] A README that reproduces the main results from a fresh clone in under 10 minutes.

The project is successful even if Isolation Forest loses. The deliverable is **evidence**, not a positive result.

### Phase 0 — Repository and scope (done)

### Phase 1 — Data pipeline and audit (Day 1)

- [ ] `src/io.py`: load `water_dataset.mat`, build `(705, 37, 11)` tensor
- [ ] `src/preprocess.py`: flatten to station-day table, add date and station ID
- [ ] Chronological split: 423 train / 282 test days
- [ ] Within-station median/IQR scaler fitted on train only
- [ ] `scripts/01_build_dataset.py` writes `data/processed/station_day.csv`
- [ ] `scripts/02_audit.py` produces:
  - [ ] between-station vs within-station variance table
  - [ ] correlation matrix / feature-family groups
  - [ ] floor-value and missing-value check
  - [ ] station × time coverage figure
- [ ] `tests/test_split.py`: no test day leaks into training statistics

**Definition of done:** the table has 26,085 rows, 11 feature columns, no missing values, and the split boundary is asserted in a test.

### Phase 2 — Detectors and fault injection (Day 2)

- [ ] `src/detectors.py`: MAD, PCA reconstruction (optional), Mahalanobis, Isolation Forest
- [ ] `src/faults.py`: spike, drift, correlation-break injectors
- [ ] Injection only into eligible features with meaningful within-station variance
- [ ] Values clipped to the observed [0, 1] range
- [ ] Fault labels stored alongside the corrupted matrix
- [ ] `tests/test_faults.py`: injected rows are labelled; clean rows are unchanged; prevalence is correct

**Definition of done:** one command produces a corrupted test set with a boolean label vector and knows which feature and which rows were changed.

### Phase 3 — Detection benchmark (Day 3)

- [ ] `scripts/03_run_detection.py`
- [ ] Fit each detector once per seed on clean train data
- [ ] Score clean and corrupted test sets
- [ ] Compute AUC-ROC, AUC-PR, recall@k, FPR at a fixed threshold
- [ ] Repeat for 5 seeds
- [ ] `results/tables/detection.csv` and `results/figures/detection_heatmap.png`
- [ ] Paired bootstrap confidence intervals for the main comparisons

**Definition of done:** a detector × fault-type table with mean ± SD and confidence intervals.

### Phase 4 — Explanation faithfulness (Day 4)

- [ ] `src/explain.py`: occlusion attribution for any detector
- [ ] Exact Mahalanobis contribution: `z_j * (Σ⁻¹ z)_j`
- [ ] `scripts/04_run_explanations.py`
- [ ] Top-1 recovery of the injected feature, MRR, mean rank
- [ ] Deletion test: remove top-attributed feature vs random feature
- [ ] Stability: top-1 agreement across seeds
- [ ] `results/tables/faithfulness.csv` and `results/figures/faithfulness.png`

**Definition of done:** for each fault type, a table showing whether the explanation points at the corrupted measurement, and how often.

### Phase 5 — Real-record analysis (Day 5, morning)

- [ ] `scripts/05_real_record.py`
- [ ] Apply the best detectors to the unlabelled test period

- [ ] Report flag concentration by station and date
- [ ] Select three case studies and plot the feature profile against station reference statistics
- [ ] `results/tables/real_flags.csv`, `results/figures/case_studies.png`

**Definition of done:** a descriptive section that clearly says these are candidate faults, not confirmed pollution events.

### Phase 6 — Report and release (Day 5, afternoon)

## Cut list (already decided)

| Cut | Reason |
|---|---|
| Extended IF as a core requirement | Low-cost optional; not needed for the story |
| PCA / LOF / One-Class SVM | More baselines than a solo project needs |
| DIFFI | Implementation risk; occlusion is a valid local attribution |
| SHAP | Slow, distorted by collinearity, no added value here |
| Stuck-sensor faults | Cross-sectional detectors cannot see them; would force temporal modelling |
| Global retrain ablation | Overlaps prior work and is numerically unstable |
| Seasonal residualisation as a full experiment | Keep as one sensitivity check |
| Multi-feature faults | Scope creep |
| Spatial modelling | Scope creep |
| Dashboard / Power BI | Out of scope |
| Deep learning | Out of scope |

## Risks and mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Fault injector bugs produce misleading labels | Medium | High | Unit tests on known indices; assert clean rows unchanged |
| Mahalanobis covariance is near-singular | Low | Medium | Use pseudo-inverse or Ledoit–Wolf shrinkage |
| IF results are unstable across seeds | Medium | Medium | 5 seeds, report SD, paired comparisons |
| Real-record flags are unverifiable | High | Medium | Keep E4 descriptive; do not claim pollution |
| Scope creep | High | High | Frozen matrix; cut list above |
| DIFFI takes too long | Medium | Low | It is a stretch item; occlusion is sufficient |
| Report written last and rushed | Medium | High | Write results incrementally from Day 3 |
